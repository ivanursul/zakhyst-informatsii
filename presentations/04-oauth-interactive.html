5 причин, чому це жахливо

Кожна причина, чому передача пароля руйнує безпеку

🔓
Повний доступ
PrintApp потрібне лише читання нотаток, але він отримує доступ до всього — видалення, зміна пароля, приватні дані
💣
Неможливість вибіркового відкликання
Щоб забрати доступ у PrintApp, Максим мусить змінити пароль — а це зламає доступ УСІМ підключеним додаткам
📢
Поширення пароля
Кожен сторонній додаток зберігає пароль. Зламали ОДИН — скомпрометовано весь акаунт
🕵
Відсутність аудиту
SecureNotes не може відрізнити запити Максима від запитів PrintApp — обидва використовують ті самі облікові дані
⚠️
Порушення принципу найменших привілеїв
Фундаментальний принцип безпеки порушено — додатки повинні отримувати мінімум дозволів, необхідних для роботи
Знайомтесь: 4 ролі

OAuth 2.0 розділяє відповідальність на 4 ролі. Натисніть на кожну, щоб дізнатися більше.

👤
Resource Owner
Максим
Користувач, який володіє даними. Максим — власник нотаток. Він вирішує, хто отримає доступ, натискаючи "Дозволити" на екрані згоди. Він ніколи не передає свій пароль.
🖨
Client
PrintApp
Сторонній додаток, який хоче отримати доступ. PrintApp хоче читати нотатки для друку. Він ніколи не бачить пароль користувача — натомість отримує обмежений токен.
🔐
Authorization Server
SecureNotes Auth
Охоронець / рецепція. Перевіряє особу Максима, показує екран згоди та видає токени. Це центр довіри, який робить всю систему безпечною.
💾
Resource Server
SecureNotes API
Сховище, де зберігаються дані. Перевіряє кожен вхідний токен — чи він дійсний? Чи не закінчився? Чи має потрібний scope? Тільки тоді повертає нотатки.
Екран згоди (Consent Screen)

Ось що бачить Максим замість того, щоб передавати свій пароль

🖨
PrintApp
printapp.example
PrintApp хоче отримати доступ до вашого акаунту SecureNotes:
  • ✅ Читати ваші нотатки — переглядати назви та вміст
  • ✅ Читати ваш профіль — переглядати ваше ім'я
🛡 PrintApp НЕ ЗМОЖЕ: видаляти нотатки, змінювати пароль, керувати спільним доступом.

До та після OAuth

Повна картина

❌ Передача пароля

  • 🔓 Повний доступ до всього акаунту
  • 💣 Зміна пароля = зламати всі додатки
  • 📢 Пароль зберігається у кожному додатку
  • 🕵 Неможливо визначити, хто що зробив
  • ⏳ Доступ ніколи не закінчується
  • 🚫 Жодного гранулярного контролю

✅ OAuth 2.0

  • 🔒 Обмежений доступ (лише notes:read)
  • 🔄 Відкликання кожного додатка окремо
  • 🔐 Пароль залишається на сервері авторизації
  • 📝 Кожен додаток ідентифікований через client_id
  • ⏰ Токени автоматично закінчуються
  • 🎯 Точний контроль через scopes
